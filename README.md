# PIONER

Ассистент, который живёт в чате и умеет:

| Что делает | Как позвать |
|---|---|
| Скачивает медиа из **TikTok**, **Instagram** (reel/пост/карусель) и **YouTube** — без вотермарки и анонимно | просто киньте ссылку |
| Генерирует картинки по описанию | `/img рыжий кот в скафандре` или «**Сгенерируй** рыжего кота» |
| Редактирует присланное фото | фото с подписью «**Сгенерируй** ему шляпу» или ответ `/edit …` на фото |
| Отвечает на вопросы про картинку/файлы | фото с подписью «что здесь изображено?» — или тем же вопросом в ответ на фото |
| Отвечает как обычная модель, помнит контекст диалога | `/ask …`, «**Ответь** …» или просто напишите ему |
| Слушает голосовые и отвечает — текстом или голосом | пришлите голосовое |
| Пересказывает содержание ролика по ссылке | `/sum <ссылка>` или «**Перескажи** <ссылка>» |
| Озвучивает текст | `/say привет` |

Плюс следит за профилями и каналами (TikTok, YouTube, Instagram) и сам постит новое, как только оно выходит.

AI-часть работает с **любым OpenAI-совместимым эндпоинтом** — свой шлюз, ключ и названия
моделей вы задаёте в `.env`. Не заполнили — бот остаётся чистым скачивальщиком, ничего не ломается.

## Что нужно
- Python 3.11+
- [uv](https://docs.astral.sh/uv/)
- (опционально) `ffmpeg` — для основного пути не требуется; желателен для отдельных форматов yt-dlp
- (опционально) доступ к любому OpenAI-совместимому API — для AI-функций

## Установка
```bash
uv sync
```

## Настройка Telegram
1. **@BotFather → `/newbot`** → получите `BOT_TOKEN`.
2. Если бот будет работать **в группе** — обязательно отключите privacy mode:
   **@BotFather → `/setprivacy` → выберите бота → Disable.**
   Без этого бот не видит обычные сообщения в группе и не поймает ни ссылки, ни обращения.
   После этого добавьте бота в группу.
3. Узнайте `TARGET_CHAT_ID` (куда поллер постит новые ролики): добавьте бота в нужный чат,
   перешлите сообщение из чата боту `@getidsbot`, либо добавьте самого бота в ваш чат.
   Id группы будет отрицательным (супергруппы/каналы — с префиксом `-100`).

## Конфиг
Скопируйте `.env.example` → `.env` и заполните поля (минимум — `BOT_TOKEN`).
Для слежения за профилями нужны одновременно `TARGET_CHAT_ID` и `TIKTOK_PROFILES`.

### AI: чат и картинки
Три обязательных поля — адрес API, ключ и хотя бы одна модель:

```dotenv
AI_API_BASE=https://api.openai.com/v1   # голый хост сам дополнится до /v1
AI_API_KEY=sk-...
AI_CHAT_MODEL=gpt-4o-mini               # текст
AI_IMAGE_MODEL=gpt-image-1              # генерация и правка картинок
```

**Каждая функция включается своей моделью.** Оставили `AI_CHAT_MODEL` пустым — команда `/ask`
вежливо скажет, что не настроена, а `/img` продолжит работать. И наоборот.

Дальше — по вкусу:

| Переменная | Зачем |
|---|---|
| `AI_IMAGE_EDIT_MODEL` | отдельная модель под правку фото; пусто → берётся `AI_IMAGE_MODEL` |
| `AI_IMAGE_API` | `images` (по умолчанию) или `chat` — см. ниже |
| `AI_IMAGE_EDIT_API` | то же отдельно для правки; пусто → берётся `AI_IMAGE_API` |
| `AI_SYSTEM_PROMPT` | характер и язык обычной модели |
| `AI_CHAT_MODE` | `off` / `mention` (по умолчанию) / `always` — см. ниже |
| `AI_CHAT_TRIGGERS`, `AI_IMAGE_TRIGGERS`, `AI_EDIT_TRIGGERS` | слова вместо команд — см. ниже |
| `AI_HISTORY_TURNS`, `AI_HISTORY_TTL_MINUTES` | глубина и срок жизни контекста |
| `AI_MAX_TOKENS`, `AI_TEMPERATURE` | потолок ответа и температура; пусто/0 → дефолты модели |
| `AI_IMAGE_SIZE`, `AI_IMAGE_COUNT` | размер и количество картинок за раз |
| `AI_TIMEOUT` | таймаут запроса, по умолчанию 180 с — картинки рисуются долго |
| `AI_RETRIES` | сколько раз повторить при 429/5xx — см. ниже |
| `AI_REGEN_BUTTON` | кнопка «Ещё вариант» под картинкой |
| `AI_CHAT_SETTINGS` | разрешить `/set` — свою модель и промпт на чат |

#### Зрение, голос и пересказ
Каждая функция включается своей моделью — пустая строка выключает только её:

```dotenv
AI_VISION_MODEL=              # фото и PDF; пусто -> AI_CHAT_MODEL, off -> выключить
AI_MEDIA_MODEL=               # видео и аудио; пусто -> AI_VISION_MODEL, off -> выключить
AI_ATTACHMENTS=true           # видео/аудио/документы уходят в модель как есть (нужна мультимодальная)
AI_ATTACHMENT_MAX_MB=20       # лимит одного вложения
AI_TRANSCRIBE_MODEL=whisper-1 # запасной путь для голосовых + пересказ роликов
AI_TTS_MODEL=tts-1            # /say и голосовые ответы
AI_TTS_VOICE=alloy
AI_VOICE_REPLY=false          # отвечать на голосовые голосом
```

- **Фото с обычным текстом.** «Что здесь изображено?» уходит в vision-модель;
  чтобы отредактировать, нужна команда `/edit` или триггер («Сгенерируй ему шляпу»).
  Если `AI_VISION_MODEL` и `AI_CHAT_MODEL` пусты, фото с текстом снова означает правку.
- **Спросить можно тремя способами:** подписью к фото, **ответом** на сообщение с фото
  или командой `/ask` в любом из этих двух видов — работает одинаково. Если ответить
  на фото, приложив ещё одно, модель получит обе картинки.
- **В группе действует `AI_CHAT_MODE`.** При `mention` (по умолчанию) ответ на **чужое** фото
  бот молча пропустит — его нужно позвать: `@ИмяБота что здесь?` тем же ответом.
  Ответ на фото, которое прислал **сам бот**, обращением уже считается — упоминание не нужно.
- **Голосовые, видео, аудио и документы.** С мультимодальной моделью (`AI_ATTACHMENTS=true`,
  по умолчанию) вложение уходит в `chat/completions` прямо рядом с текстом — как фото.
  Вопрос — подпись к файлу или ответ на него; файл без подписи бот кратко опишет сам.
  В группе всё это ловится по тем же правилам, что и текст (`AI_CHAT_MODE`): по умолчанию
  только ответом боту.

  | Что прислали | Как уходит в шлюз | Какая модель |
  |---|---|---|
  | фото | `image_url` | `AI_VISION_MODEL` |
  | PDF и прочие бинарники | `file`, при `AI_DOC_PART=inline` — data-URI | `AI_VISION_MODEL`, в режиме inline — `AI_MEDIA_MODEL` |
  | txt, csv, json, код | текст вклеивается в промпт | `AI_CHAT_MODEL` |
  | видео, GIF, кружок | `input_audio` | `AI_MEDIA_MODEL` |
  | аудио, голосовое | `input_audio` | `AI_MEDIA_MODEL` |

- **Пересказ** (`/sum`, «Перескажи») скачивает ролик, отдаёт дорожку в расшифровку и просит
  модель пересказать по `AI_SUMMARY_PROMPT`. Ограничен `AI_TRANSCRIBE_MAX_MB` (у шлюзов
  обычно 25 МБ) — для длинных видео упрётся в лимит.

#### `AI_IMAGE_API`: два способа получить картинку
Шлюзы отдают картинки по-разному, поэтому транспорт выбирается флагом:

- **`images`** (по умолчанию) — классический OpenAI: `POST /images/generations` и
  `POST /images/edits`. Подходит для `gpt-image-1`, `dall-e-3` и большинства шлюзов-прокси к OpenAI.
- **`chat`** — картинка приходит внутри обычного `POST /chat/completions`. Так работают
  Gemini-образные модели (`nano-banana` и родня) через OpenRouter и похожие шлюзы.

Если генерация и правка живут на разных API — задайте `AI_IMAGE_EDIT_API` отдельно.
Ответ разбирается терпимо: и `b64_json`, и ссылка, и `data:`-URI внутри текста — всё подхватится.

#### Слова-триггеры: команды можно не писать
Первое слово сообщения заменяет команду. Списки задаются через запятую, регистр не важен,
триггером может быть и фраза из нескольких слов:

```dotenv
AI_CHAT_TRIGGERS=Ответь,Объясни,Расскажи
AI_IMAGE_TRIGGERS=Сгенерируй,Нарисуй
AI_EDIT_TRIGGERS=Отредактируй,Измени,Переделай
```

| Сообщение | Куда уходит |
|---|---|
| `Ответь что такое Python` | обычная модель |
| `Сгенерируй рыжего кота` | генерация картинки |
| `Сгенерируй ему шляпу` **+ приложенное фото** | правка этого фото |
| `Сгенерируй в стиле аниме` **ответом на фото** | правка того фото |
| `Отредактируй: убери фон` | правка (нужно фото) |

Триггер для картинок сам решает, рисовать с нуля или править: **есть картинка в сообщении
или в том, на которое отвечаете → идём в edit, нет → в генерацию.** Отдельный
`AI_EDIT_TRIGGERS` нужен, когда хочется сказать про правку явно.

#### `AI_CHAT_MODE`: когда бот влезает в разговор
- **`off`** — модель отвечает только на явную команду `/ask`.
- **`mention`** *(по умолчанию)* — в личке отвечает на любое сообщение; в группе только когда
  к нему обратились: `@ИмяБота вопрос` или ответом на его сообщение. Тихо в общем чате.
- **`always`** — отвечает на каждое сообщение без ссылки. Для группы обычно шумно.

Ссылка на видео всегда обрабатывается как ссылка — какой бы режим ни стоял.

### Прокси
Заполните `PROXY_URL` — общий прокси. Кто именно им пользуется, задаётся раздельно:

| Переменная | По умолчанию | Канал |
|---|---|---|
| `PROXY_TELEGRAM` | `on` | Bot API (`api.telegram.org`) |
| `PROXY_DOWNLOADS` | `on` | скачивание (tikwm + yt-dlp) |
| `PROXY_AI` | `off` | запросы к моделям |

Каждая принимает `on` (взять `PROXY_URL`), `off` (напрямую) или **свой URL** — например,
Telegram через `socks5://a:1080`, а видео через `http://b:8080`.

`http(s)` и `socks5` работают из коробки (extra `httpx[socks]` для скачивания и
`aiohttp-socks` для Telegram уже в зависимостях), креды зашиваются в URL:
`http://user:pass@host:port` или `socks5://user:pass@host:1080`.

### Cookies (для Instagram / возрастных видео)
Instagram почти всегда требует залогиненную сессию. Укажите одно из:
- `COOKIES_FILE` — путь к `cookies.txt` (формат Netscape), выгруженному из браузера;
- `COOKIES_FROM_BROWSER` — имя браузера (`chrome`, `firefox`, `edge`…), откуда брать cookies на лету.

## Команды
| Команда | Что делает |
|---|---|
| `/help` | список того, что реально включено в этой сборке |
| `/img <описание>` | нарисовать картинку (алиасы: `/image`, `/gen`) |
| `/edit <что поменять>` | правка фото — подписью к фото или ответом на него (алиас: `/redraw`) |
| `/ask <вопрос>` | спросить модель; ответом на сообщение — вместе с его текстом (алиас: `/chat`) |
| `/sum <ссылка>` | пересказать ролик; ответом на сообщение со ссылкой — без аргумента (алиасы: `/summary`, `/tldr`) |
| `/say <текст>` | озвучить; ответом на сообщение — его текст (алиасы: `/voice`, `/tts`) |
| `/set` | показать настройки чата; `/set prompt Ты пират`, `/set reset` — см. ниже |
| `/reset` | забыть контекст диалога (алиас: `/forget`) |

### Настройки на чат: `/set`
Модель и промпт можно переопределить в конкретном чате, не трогая `.env` и не перезапуская бота.
Значения лежат в `state.db` и переживают рестарт.

```
/set                          показать, что сейчас
/set prompt Ты отвечаешь как пират
/set chat_model gpt-4o
/set image_model gpt-image-1
/set size 1024x1536
/set prompt -                 сбросить один ключ (снова из .env)
/set reset                    сбросить всё
```

Выключается через `AI_CHAT_SETTINGS=false`.

Команды видны в меню Telegram — бот регистрирует их при старте, показывая только настроенные.
Вместо любой из них можно использовать слово-триггер (`Сгенерируй …`, `Ответь …`) — см. выше.

## Как это работает / детали
- **TikTok.** Сначала `tikwm.com` (поток без вотермарки в HD, плюс фото-посты),
  при сбое — фолбэк на `yt-dlp`. Порядок меняется в `PROVIDER_ORDER`.
- **Instagram.** Через `yt-dlp`: reels/видео, а также фото и карусели (несколько фото/видео
  уходят одним альбомом). Для большинства постов нужны cookies — см. выше.
- **YouTube.** Через `yt-dlp`. Разрешение ограничено `YOUTUBE_MAX_HEIGHT` (по умолчанию 720p),
  чтобы файл влезал в лимит Bot API без сборки `ffmpeg`.
- **Слежка** берёт источники из `TIKTOK_PROFILES` (старый формат: имя или `@handle`) и
  `WATCH_PROFILES` (полные ссылки на что угодно: TikTok-профили, YouTube-каналы,
  Instagram-профили). Списки складываются, дубли отбрасываются.
- **Первый запуск слежки** за источником: бот запоминает текущие посты и **не заливает
  весь бэклог** — постит только то, что выйдет после старта.
- **Контекст диалога** хранится в памяти процесса, отдельно для каждой пары «чат + пользователь»,
  и сбрасывается по `/reset`, по таймауту `AI_HISTORY_TTL_MINUTES` или при перезапуске бота.
- **Правка фото** берёт картинку из самого сообщения и из того, на которое отвечаете, — так
  можно скормить модели сразу две (например, «перенеси стиль со второй на первую»).
- **Лимиты Telegram.** Файл — 50 МБ (`MAX_FILE_SIZE_MB`), если больше, бот пришлёт ссылку
  на оригинал; для альбомов — пропустит слишком тяжёлые элементы и скажет об этом.
  Сгенерированные картинки тяжелее 10 МБ уходят документом, длинные ответы модели режутся
  по абзацам на сообщения по 4096 символов. Снять лимит на файлы (до 2 ГБ) можно только
  подняв локальный Bot API server.

## Тесты и самопроверка
```bash
uv run pytest -q
```

`pytest` лежит в группе `dev`, а её `uv sync` ставит по умолчанию — отдельных действий не нужно.

Тесты офлайновые (шлюз и Telegram замоканы), проходят примерно за 6 секунд и покрывают
разбор ответов шлюза, повторы, маршрутизацию сообщений, триггеры и хранилище.

Бот **гоняет их сам**: один раз при старте и дальше раз в `SELFCHECK_INTERVAL_HOURS`
(по умолчанию 12). Результат уходит в лог, а при падении — сообщением в `TARGET_CHAT_ID`.

| Переменная | Что делает |
|---|---|
| `SELFCHECK_ENABLED` | включить самопроверку (по умолчанию да) |
| `SELFCHECK_INTERVAL_HOURS` | период; `0` — только при старте |
| `SELFCHECK_REPORT` | `off` / `fail` (по умолчанию) / `always` — что слать в чат |

Смысл в том, чтобы поймать поломку после обновления зависимостей (`aiogram`, `yt-dlp`,
`pydantic`) раньше, чем на неё наткнётся пользователь. Проверка идёт в отдельном процессе
и работе бота не мешает. Чего она **не** ловит — смену API у самих платформ и шлюза:
тесты не ходят в сеть, это видно только по обычным ошибкам в чате.

## Обновление на сервере
Версии зависимостей резолвятся при установке. После `git pull`
достаточно обычной синхронизации:

```bash
git pull
uv sync      # подтянет версии не ниже тех, что указаны в pyproject
uv run ttbot
```

Если на сервере уже лежит старый `uv.lock`, он держит прежние версии — тогда сначала
пересоберите его:

```bash
uv lock --upgrade && uv sync
# или точечно: uv lock --upgrade-package yt-dlp && uv sync
```

`yt-dlp` стоит освежать регулярно и без всякого повода: платформы ломают его чаще всего.

## Заметки
- Сторонние сервисы и сами платформы периодически меняют API — возможны временные поломки;
  для TikTok цепочка из двух провайдеров это сглаживает. Если что-то отвалилось —
  первым делом обновите `yt-dlp` (см. выше).
- Ошибки шлюза бот показывает как есть (`HTTP 401: Incorrect API key…`) — по такому сообщению
  сразу видно, дело в ключе, модели или деньгах на балансе.

## Структура
```
src/ttbot/
  app.py        # сборка и запуск (long-polling + поллер + самопроверка)
  bot.py        # хэндлеры aiogram, отправка медиа и мост к модели
  poller.py     # фоновая проверка профилей и каналов
  media.py      # детект платформы, провайдеры (tikwm/yt-dlp), цепочка загрузки
  ai.py         # клиент к OpenAI-совместимому API: чат, картинки, голос, повторы
  state.py      # просмотренные посты и настройки чатов (SQLite)
  selfcheck.py  # прогон тестов при старте и по расписанию
  config.py     # настройки из .env
tests/          # офлайновые тесты, их же гоняет самопроверка
```
